# FURA — AI-агент «РОП»: запуск

Агент щоранку перевіряє CRM як керівник відділу продажів: ставить задачі команді й пише висновки.
**Цифри рахує код, Claude лише пояснює їх.** Звіт бачать тільки «Керівник» і «Адмін». Менеджери бачать лише свої задачі на головній.

```
pg_cron (08:30 Київ) ─▶ fura-rop ─▶ запити · ліди · клієнти · угоди · AI-продажі
                                  │
                       код: цифри + проблеми за порогами
                                  │
                ┌─────────────────┴───────────────────┐
          rop_tasks → «Задачі від РОПа»        Claude → висновки
          на головній у відповідального        rop_reports → сторінка «РОП»
```

## Нові файли

| Файл | Що це |
|---|---|
| `rop.sql` | Таблиці `rop_settings`, `rop_reports`, `rop_tasks`, доступ, розклад |
| `bot/fura-rop.ts` | Серверна функція: розрахунки, задачі, висновки Claude, призначення лідів |
| `rop.html / .js / .css` | Сторінка «РОП» (тільки head / admin) |
| `rop-tasks.js` | Плитка «Задачі від РОПа» на головній |
| `shell.js` | + пункт меню «РОП» (видно лише head / admin) |
| `home.html` | + блок задач |
| `theme.css` | + приховування пунктів меню за роллю |
| `*.html` | оновлена версія `?v=` у посиланнях на стилі й скрипти, щоб браузер узяв нові файли |

## Крок 1. База (2 хв)

Supabase → SQL Editor → вставити `rop.sql` → Run. Має показати 3 таблиці.

## Крок 2. Секрети функції

Supabase → Edge Functions → Secrets:

| Секрет | Обов'язково | Примітка |
|---|---|---|
| `ANTHROPIC_API_KEY` | так | уже є для fura-agent / fura-sales |
| `ROP_CRON_SECRET` | так | будь-який довгий випадковий рядок |
| `ROP_MODEL` | ні | типово `claude-sonnet-5-5` |

Без ключа Claude звіт працює, але показує лише цифри й 5 найтерміновіших задач, без висновків.

## Крок 3. Розгортання

```bash
supabase functions deploy fura-rop --no-verify-jwt
```
Або через редактор: Edge Functions → Deploy a new function → `fura-rop` → вставити `bot/fura-rop.ts` → Deploy → вимкнути «Verify JWT».

## Крок 4. Розклад

У `rop.sql`, блок 7: розкоментувати, підставити `ROP_CRON_SECRET`, виконати.
Функцію викликають кожні 15 хв з 04:00 до 10:00 UTC. Вона сама перевіряє час у Києві й готує звіт один раз на день, тому перехід на літній чи зимовий час нічого не ламає.

## Крок 5. Перший запуск

Відкрити «РОП» → **«Оновити зараз»**. За хвилину з'явиться звіт і задачі.
Якщо вгорі написано «частину даних не прочитано», наведіть курсор на цей напис: там видно, яку таблицю функція не змогла прочитати.

| Перевірка | Поріг | Кому задача |
|---|---|---|

| Ставка в статусі «Відповідь» без реакції Sales | 2 год | Sales |
| Прострочений «наступний контакт» по ліду | дата минула | Sales |
| «Новий» / «Контакт» без жодної дії й без дати контакту | 7 дн. | Sales |
| «Переговори» | 14 дн. | Sales |
| Клієнт «Працюємо» без запитів і угод | 20 дн. | Sales |
| Немає оплати після розвантаження | 14 дн. | Sales угоди |

Пріоритет: 🔴 терміново (перевищено норму вдвічі, гроші, клієнт чекає) · 🟠 сьогодні · ⚪ коли буде час.

## Як живуть задачі

- Задача з'являється у відповідального на **головній**, у блоці «Задачі від РОПа».
- Якщо проблему вирішили в CRM (відповіли на запит, поставили оплату, оновили лід), агент **сам закриває задачу** під час наступної перевірки.
- «Зроблено» закриває задачу одразу.
- «Не актуально» ховає задачу на 7 днів, потім вона повернеться, якщо проблема лишилась.
- Одна проблема — одна задача: при повторних перевірках агент оновлює текст, а не створює дубль.

## Правила, вшиті в агента

- Claude отримує лише вже пораховані цифри й не має права вигадувати свої.
- Агент нічого не змінює в CRM сам. Єдиний виняток — «Призначити» відповідального за лід, яке натискає керівник; запис про це з'являється в історії ліда.
- Звіти й пороги закриті правилами бази (RLS): навіть через API їх бачать лише head / admin.

## Наступний етап

Контроль переписки з клієнтами (Outlook, Telegram, Viber, WhatsApp): швидкість відповіді, тон, чи названо ставку.
Спершу ці канали треба підключити до FURA.
